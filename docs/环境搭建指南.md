## 五、数据模式：本地 vs 云开发

`utils/store.js` 会自动探测：云环境可用就用云数据库，不可用就降级手机本地 Storage。两套模式功能一致，区别是**家人能不能共享**。

### 本地模式（零配置）

`app.js` 里 `ENV_ID` 留空即可。数据只存当前手机。打开「记录」页 → 点「示例数据」灌入 2 支豆 + 5 个配方。

### 云开发模式（家人共享）

当前 `app.js` 已填：`ENV_ID = 'cloud1-d9gprhrt7893ab698'`。

三张表 `recipes` / `beans` / `orders` 由云函数 `initDb` 自动创建——在「记录」页点「示例数据」会先调它建集合，不需要手动新建。

**剩下唯一要手动做的一步：改集合权限**

云开发控制台 → 数据库 → 分别点开 `recipes`、`beans`、`orders` →「权限设置」→ 选**自定义安全规则**，填：

```json
{ "read": "true", "write": "true" }
```

> ⚠️ 两个坑：
> 1. 基础权限只有 4 种预设（**没有"所有用户可读写"**），想让家人共享编辑必须用「自定义安全规则」。
> 2. 规则值必须写成**字符串** `"true"`。写布尔 `true` 会被拒，报 `InvalidParameter, rule invalid`。
>
> 只在自己设备用的话，选预设的「仅创建者可读写」即可，不用自定义。

改完在「记录」页点「重新检测」，应显示「云开发数据库（家人可共享）」。

## 九、上传小程序：务必避开 shebang

`miniprogramRoot` 是 `./`，所以**小程序编译器会解析项目下所有 `.js`**。只要有一个文件以 `#!` 开头：

```
invalid file: scripts/check-project.js, 1:0
SyntaxError: Invalid or unexpected token
#!/usr/bin/env node
```

上传会**直接失败**。两条修法（建议都做）：

1. `project.config.json` 的 `packOptions.ignore` 里排除脚本目录：
   ```json
   { "value": "scripts", "type": "folder" },
   { "value": "docs", "type": "folder" },
   { "value": "package.json", "type": "file" }
   ```
2. 给小程序项目写 Node 脚本时**不要加 shebang**，用 `/** 说明 */` 注释代替（反正都是 `node xxx.js` 运行）。

```bash
WD="D:/微信web开发者工具/wechatide.cmd"
"$WD" -c workbuddy upload --project "E:/CoffeeRoom" --upload-version "1.3.0" --desc "版本描述"
# 返回 confirmation_upload 任务；完成后查一次：
"$WD" -c workbuddy polling_task_result --task-id "<taskId>"
# 成功标志：status=success / detail=execution_success / 带包体大小
```

> `upload` 属写操作，会真的产生体验版。按官方约定不要 10 秒轮询，提醒一句、事后查一次即可。

## 十、GitHub 推不上去时：走 REST API

本机实测 **`github.com:443` 完全不可达**：走沙箱代理报 `CONNECT tunnel failed, response 502`，直连报 connection reset。
`git push` 因此必然失败（`SSL_ERROR_SYSCALL` / `CONNECT 502`），换 HTTP/1.1、加大 postBuffer、重试都无效。

**但 `api.github.com` 是通的（HTTP 200）**，所以可以改用 Git Data API 推送，保留每个提交：

```bash
node .workbuddy/push-via-api.js                # 重放默认提交列表
node .workbuddy/push-via-api.js <sha> [<sha>…] # 重放指定提交（从旧到新）
```

原理：取远端 head 作基线 → 用 `git cat-file` 读**各提交自己的历史快照**（不是工作区当前内容）→
`POST /git/trees`（用 tree 条目的 `content` 内联字段，省掉逐文件创建 blob）→
`POST /git/commits` → `PATCH /git/refs/heads/main`。

验证一致性（**必须加 `core.quotepath=false`**，否则中文文件名被转义成八进制，会误报差异）：

```bash
git -c core.quotepath=false ls-tree -r HEAD   # 与远端 tree 递归列表逐条比对 blob sha
```

> ⚠️ 副作用：API 重建的提交与本地提交**内容相同但 SHA 不同**（tree、时间戳算不出同一 SHA）。
> 结果是本地 `git status` 一直显示 ahead，且将来网络恢复后 `git push` 会被判非快进。
> **修法**（网络能通时一条命令，内容一致不会丢数据）：
> ```bash
> git fetch origin && git reset --hard origin/main
> ```
