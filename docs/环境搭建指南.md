## 二、👤 你必须手动做的一步：安装微信开发者工具

### 为什么我装不了

微信开发者工具是 GUI 程序，安装后**必须用微信扫码登录**才能编译、预览、上传云函数。这两步都要求真人在场，命令行走不通。当前这台机器上全盘搜索（`C:` `D:` `E:`）未发现任何 `cli.bat` / `微信web开发者工具` 目录。

### 安装步骤

1. 下载地址：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html
   - 建议装 **Nightly 版**（≥ 2.02.2608312）。Nightly 内置了 CLI / MCP 能力，命令行部署云函数、订阅消息回调都靠它；稳定版功能会滞后。
2. 安装完成后打开工具，**用小程序管理员微信扫码登录**。
3. `项目` → `导入项目`：
   - 目录：`E:\CoffeeRoom`
   - AppID：`wxaa402d1ea6ebb696`（已写在 `project.config.json`）
4. 打开后应能直接编译。若提示云开发未开通，去「云开发」控制台确认环境 `cloud1-d9gprhrt7893ab698` 存在。

### 打开服务端口（想用命令行部署就必做）

`设置` → `安全设置` → 打开 **服务端口**。之后命令行才能调用：

```bash
cd "C:\Program Files (x86)\Tencent\微信web开发者工具"   # 按实际安装路径调整

cli.bat islogin                                             # 检查登录状态
cli.bat cloud env list --project E:\CoffeeRoom               # 查看云环境
cli.bat preview --project E:\CoffeeRoom -f image -o qr.png    # 编译 + 生成预览二维码
cli.bat upload --project E:\CoffeeRoom -v 1.1.0 -d "v1.1 豆量闭环+看板+计时器"  # 上传体验版
cli.bat cloud functions deploy -e cloud1-d9gprhrt7893ab698 -n initDb --project E:\CoffeeRoom
```

> ⚠️ 实测坑：如果开发者工具已经开着，CLI 授权会因**单例锁**超时。执行授权前先**完全退出**开发者工具，再跑命令，过程中会弹两个确认框（「请求连接 CLI」和「MCP 客户端授权」），都需要点允许。


它会检查 7 类问题：

| 检查项 | 说明 |
|---|---|
| JSON 可解析 | 所有 `.json`（含 `app.json` / 各页 `.json` / `project.config.json`） |
| JS 语法 | 所有 `.js` 走 `node --check` |
| 页面四件套 | `app.json` 里登记的每个页面，`.js/.json/.wxml/.wxss` 是否齐全 |
| 事件绑定 | WXML 里 `bindtap`/`catchtap` 绑定的方法，页面 JS 里是否真的定义了 |
| 图片引用 | `<image src="本地路径">` 与 tabBar 图标文件是否存在 |
| 标签闭合 | WXML 标签是否闭合平衡 |
| 云函数依赖 | 提醒哪个云函数还没 `npm install` |

当前基线：`JS 16 · JSON 12 · WXML 7 · 页面 7` → **✓ 全部检查通过**。

## 五、数据模式：本地 vs 云开发

`utils/store.js` 会自动探测：云环境可用就用云数据库，不可用就降级手机本地 Storage。两套模式功能一致，区别是**家人能不能共享**。

### 本地模式（零配置）

`app.js` 里 `ENV_ID` 留空即可。数据只存当前手机。打开「记录」页 → 点「示例数据」灌入 2 支豆 + 5 个配方。

### 云开发模式（家人共享）

当前 `app.js` 已填：`ENV_ID = 'cloud1-d9gprhrt7893ab698'`。

三张表 `recipes` / `beans` / `orders` 由云函数 `initDb` 自动创建——在「记录」页点「示例数据」会先调它建集合，不需要手动新建。

**剩下唯一要手动做的一步：改集合权限**

云开发控制台 → 数据库 → 分别点开 `recipes`、`beans`、`orders` →「权限设置」→ 选**自定义安全规则**，填：

```json
{ "read": "true", "write": "true" }
```

> ⚠️ 两个坑：
> 1. 基础权限只有 4 种预设（**没有"所有用户可读写"**），想让家人共享编辑必须用「自定义安全规则」。
> 2. 规则值必须写成**字符串** `"true"`。写布尔 `true` 会被拒，报 `InvalidParameter, rule invalid`。
>
> 只在自己设备用的话，选预设的「仅创建者可读写」即可，不用自定义。

改完在「记录」页点「重新检测」，应显示「云开发数据库（家人可共享）」。

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `detected dubious ownership in repository` | Git 认为目录属主不明（跨盘符常见） | 已处理：`git config --global --add safe.directory E:/CoffeeRoom` |
| 记录页显示「本地存储（仅本机）」 | 云环境不可用，自动降级 | 检查 `app.js` 的 `ENV_ID`、云环境是否开通、集合权限是否配好，然后点「重新检测」 |
| 报 `InvalidParameter, rule invalid` | 安全规则写成了布尔 `true` | 改成字符串 `"true"` |
| 报 `collection not exists` / `-502005` | 集合未创建 | 「记录」页点「示例数据」触发 `initDb`，或去控制台手动建 `recipes`/`beans`/`orders` |
| 本地模式下封面图重启后消失 | 本地模式保存的是临时路径 | 属已知限制；用云开发模式即可正常保存到云存储 |
| CLI 授权超时 | 开发者工具单例锁 | 完全退出开发者工具后重试 |
| 云函数部署失败 | Node 版本 / 目录结构 / EnvId 不对 | 确认函数目录含 `index.js` + `package.json`，EnvId 与 `app.js` 一致，CLI 已登录 |
