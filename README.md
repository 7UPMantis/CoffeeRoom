# 咖屋 · CoffeeRoom

给家人朋友用的咖啡小程序：记配方、按分类点单、管咖啡豆、冲煮计时。

## 设计原则：一页一个视角

这个产品的核心约束是**不在同一页混两种人的视角**：

```
点单（顾客说要什么）→ 待做队列（咖啡师认领）→ 冲煮计时（按配方执行）→ 记录（含扣豆）
```

| 页面 | 视角 | 只放 | 明确不放 |
|---|---|---|---|
| 点单 | 顾客 | 饮品名、分类、标签、杯数、给谁做、备注、选豆 | 余量数字、库存警告、冲煮入口、粉水比/水温/研磨度 |
| 配方 | 咖啡师 | 待做队列、粉水比、水温、研磨、器具、时长、分步做法、开始冲煮 | — |
| 咖啡豆 | 库存 | 余量、养豆期、用途标签、该处理了（低余量/临期/未标用途） | — |
| 记录 | 复盘 | 杯数统计、看板、筛选、每款实际用豆 | — |

## 功能

| 模块 | 说明 |
|------|------|
| **点单** | 按分类标签浏览饮品，加减杯数，填写「给谁做」和备注。**下单时选豆**——只列出符合这款饮品用途的豆（手冲豆不会出现在奶咖里），提交后按所选豆的用量自动扣减 |
| **配方** | **待做队列**（点单后的待制作清单，点开直接进冲煮）、咖啡豆用量、粉水比、器具、研磨度、水温、萃取时间、分步骤做法、封面图、标签；可设「常喝」 |
| **咖啡豆** | **用途标签**（意式/手冲/冷萃/通用）、产地/处理法/烘焙度、养豆期与保质期自动计算、余量百分比、风味标签、**「该处理了」清单**（低余量/临期/未标用途）。删除时会列出在用配方并解绑引用 |
| **记录** | 点单历史（标记完成/删除）、本月与累计杯数、累计耗豆克数、近 7 日杯数柱状图、分类占比、成员排行、最常点；按成员与状态筛选。删除记录会把豆量还回豆仓 |
| **冲煮** | 从配方或待做队列一键开始：倒计时、分步清单打勾、±15s 微调、到点震动、屏幕常亮；带订单上下文，做完可标记该单完成 |

### 选豆是怎么过滤的

咖啡豆带**用途标签**，配方声明**所需豆用途**，下单时按兼容表筛：

| 配方需要 | 可选豆标签 |
|---|---|
| 意式豆（浓缩/奶咖） | 意式、通用 |
| 手冲豆（手冲/虹吸/法压） | 手冲、通用 |
| 冷萃豆 | 冷萃、**手冲**、通用（冷萃本来就用浅中烘的手冲豆） |
| 不限 | 全部 |

配方的所需用途**留空会自动推导**：器具优先（意式机→意式、手冲壶→手冲、冷萃瓶→冷萃），器具判断不出来再看分类。

排序：**专用豆 → 通用豆 → 未标注用途**；同组内余量多的在前。未标注用途的豆仍会列出（避免历史数据消失），但会标注提示补标。

### 豆量闭环

```
点单提交 ──► 按 (所选豆 · 配方 dose × 杯数) 聚合 ──► 扣减该豆 remaining
                                                      │
删除记录 ──► 读订单里的 beanUsage ────────────────► 还回 remaining（以 weight 为上限）
```

- 没选到豆 / 没填用量 → 不参与扣减
- 豆量不足仍要下单 → 弹确认框列出差额，确认后扣到 0，也可以回去换豆
- 回补以 `weight` 为上限，不会补出「余量 > 总量」

### 养豆 / 保质期时间轴

从烘焙日起算，三个节点可自定义（默认 7 / 45 / 90 天）：

```
0 ─── 养豆期 7 天 ─── 最佳风味到 45 天 ─── 衰退到 90 天 ─── 已过保质期
      蓝色「养豆中」        绿色「最佳风味」      橙色「风味衰退」      红色「已过保质期」
```

### 云开发模式（家人共享）

| 项 | 值 |
|---|---|
| AppID | `wxaa402d1ea6ebb696` |
| 云环境 ID | `cloud1-d9gprhrt7893ab698`（已写入 `app.js` 的 `ENV_ID`） |

三个集合（`recipes` / `beans` / `orders`）由云函数 **`initDb`** 自动创建，
无需手动新建——在「记录」页点「示例数据」时会先调用它建集合，再灌入示例数据。

**剩下唯一要手动做的一步：改集合权限**

云开发控制台 → 数据库 → 分别点开 `recipes`、`beans`、`orders` →
「权限设置」→ 选**自定义安全规则**，填：

```json
{ "read": "true", "write": "true" }
```

> ⚠️ 两个注意点：
> 1. 基础权限只有 4 种预设（**没有"所有用户可读写"**），想让家人共享编辑必须用「自定义安全规则」。
> 2. 规则值要写成**字符串** `"true"`。写布尔 `true` 会被拒绝，报 `InvalidParameter, rule invalid`。
>
> 若只在自己设备用，选预设的「仅创建者可读写」即可，不用自定义。

改完后「记录」页点「重新检测」，应显示「云开发数据库（家人可共享）」。

## 数据层说明

`utils/store.js` 对外只暴露 `recipes / beans / orders` 三个对象的
`list / get / add / update / remove`，内部自动判断用云数据库还是本地 Storage：

- 云模式：一次性翻页取回（小程序端单次 `get` 上限 20 条），在内存里过滤排序，避开 `where + orderBy` 的索引问题
- 云环境不可用（未填 ID、未开通、无权限）时自动降级本地，功能照常可用

`utils/stock.js` 是业务层，负责「按用途筛豆」与「点单换豆量」两件事，不直接碰数据库连接。

## 已知限制

- 图片上传仅在云模式下会落到云存储；本地模式保存的是临时路径，重启后失效
- 云模式列表 `limit` 上限 100 条，记录超过后看板统计会偏小（已列入路线图 Next 的 X2）
- 未标注用途的豆会出现在所有配方的可选列表里（有提示，但不会强制拦截）
- 扣豆按「所选豆的用量」计算；若冲煮时临时换豆，需手动改余量（回写实际用豆已列入 Later 的 L1）
- 删除咖啡豆会解绑配方引用，但**不会**回收历史订单里的 `beanUsage` 记录（历史耗豆仍算在统计里，属预期行为）
